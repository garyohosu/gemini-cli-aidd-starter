# spec-to-design

## 役割
`SPEC.md` を読み、設計ドキュメント群を順番に生成する。  
各成果物は **生成 → 確認 → 必要なら修正 → 次へ** の順で進める。

## 入力
- `SPEC.md`
- `QandA.md` があれば参照
- 既存の設計書があれば差分を見て再利用する

## 出力
- `USECASE.md`
- `SEQUENCE.md`
- `CLASS.md`
- `UI.md`
- `TESTCASE.md`
- 必要なら `QandA.md`

## 全体ルール
- 図が必要な成果物は Mermaid を使う
- ASCII 図だけで済ませない
- 後工程へ影響する曖昧点は `QandA.md` に残す
- 軽微な表記ゆれはその場で直す

## フェーズ0: 仕様確認
やること:
- `SPEC.md` を読む
- 対象ユーザー、制約、入出力、例外条件を整理する
- 後工程へ影響する曖昧点があれば `QandA.md` に記録する

## フェーズ1: USECASE.md
内容:
- アクター
- システム境界
- 主要ユースケース
- ユースケースの簡潔な説明

形式:
- Mermaid `flowchart` を含める

確認:
- `SPEC.md` と矛盾していないか
- 主要ユースケースが漏れていないか
- Mermaid が壊れていないか

## フェーズ2: SEQUENCE.md
内容:
- main flow
- 主要分岐
- 失敗時の基本挙動

形式:
- Mermaid `sequenceDiagram` を含める

確認:
- `USECASE.md` とつながっているか
- 処理順が破綻していないか
- Mermaid が壊れていないか

## フェーズ3: CLASS.md
内容:
- 主要責務
- クラスやモジュールの役割
- 依存関係

形式:
- Mermaid `classDiagram` を含める

確認:
- `SEQUENCE.md` の責務と合っているか
- 過剰設計になっていないか
- Mermaid が壊れていないか

## フェーズ4: UI.md
内容:
- 主要画面
- 画面遷移
- 入力項目
- 表示状態
- エラー状態
- 空状態
- 権限なし状態が必要ならその扱い

形式:
- 画面遷移がある場合は Mermaid を含める

確認:
- 主要フローが表現されているか
- 例外状態が抜けていないか
- Mermaid が壊れていないか

## フェーズ5: TESTCASE.md
内容:
- 正常系
- 異常系
- 境界値
- 権限や入力不足などの失敗系
- 重要な回帰観点

形式:
- 箇条書きまたは表現しやすい Markdown

確認:
- 前フェーズの主要仕様をテストで拾えているか
- 明らかな穴がないか

## 各フェーズの出力形式
- 生成または更新したファイル
- 今回確認したこと
- 修正した点
- `QandA.md` に追加した項目
- 次に進むフェーズ
