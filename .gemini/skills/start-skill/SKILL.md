# start-skill

## 役割
現在のワークスペースの状態を確認し、次に行うべき作業を判断してそのまま進める。  
「どの skill を使うか選ぶだけ」で終わらせない。  
必要なら設計、実装、レビューまで進める。

## まず確認するもの
- `SPEC.md`
- `QandA.md`
- `USECASE.md`
- `SEQUENCE.md`
- `CLASS.md`
- `UI.md`
- `TESTCASE.md`
- 直近で変更されたコード
- 既存のレビュー結果
- 日報や運用ログがある場合はその内容

## 判定ルール
1. ユーザーがレビュー依頼をしている  
   → 現在の差分または対象ファイルをレビューする

2. `SPEC.md` があり、設計書群が不足している  
   → `spec-to-design` の流れで設計書を起こす

3. `QandA.md` に未解決の重大項目がある  
   → 影響範囲を整理し、解決可能なところまで進める

4. 実装対象が明確で、設計書がそろっている  
   → 実装を進める

5. 実装が済んでいそうだが検証不足  
   → テスト確認とレビューを行う

## 実行手順
1. 主要ファイルの有無と更新状況を確認する
2. 今のフェーズを判断する
3. 必要なら設計書生成へ進む
4. 必要なら実装へ進む
5. 作業後にレビューする
6. 残る不明点があれば `QandA.md` に追記する
7. 次工程を短く提案する

## レビュー観点
- 前フェーズとの重大な矛盾
- 必須項目の欠落
- Mermaid 構文エラー
- テスト不足
- 明確なバグ

## 出力形式
- 今回判断したフェーズ
- 実行した作業
- 更新したファイル
- 残課題
- 次の推奨アクション

## 注意
- 不明点を全部その場で解決しようとしない
- 後工程に効くものだけ `QandA.md` に残す
- 迷ったら大きく作らず、小さく進める
